# RDK X5 首机联调与验收

## A. 启动与登录 X5

1. 按板型选用地瓜机器人官方 RDK X5 Ubuntu 22.04 Server ARM64 镜像。在 Windows 用 Rufus 或 RDK Studio 烧录到确认过的 microSD。烧录会覆盖该卡。
2. 断电插卡，给 X5 单独供电。用调试串口查看启动日志，或使用网线直连验证 SSH。官方镜像的默认有线地址通常为 `192.168.127.10/24`。确认使用默认镜像时，可临时给电脑的直连有线口配置 `192.168.127.100/24` 后尝试 `ssh sunrise@192.168.127.10`。
3. 登录后执行以下命令。验收目标为 SSH 可用、Ubuntu 22.04、`aarch64` 和 Python 3.10。

```bash
cat /etc/os-release
uname -m
python3 -V
ip -br address
```

烧录后 Windows 可见的分区仅能证明镜像写入了卡。X5 登录成功后，才能确认系统启动。

## B. 部署

在 X5 上按合作方版本部署遥操作、数采及推理控制工程。现场手册的工程目录为 `/userdata/lumos_x5`。先查已有部署和环境，再按对应版本手册执行环境自检。这个仓库的 [核心安装](../README.md#核心安装) 可独立运行，用于观察设备枚举。

## C. 硬件自检

接线前让两臂保持断电，固定底座并支撑从臂。确认急停可用、工作区清空，按设备线束标识接主臂 USB 串口、从臂 CAN 和腕部相机。

| 检查 | 现场验收 |
| --- | --- |
| 腕部相机 | 彩色流可用，640×480@30 fps 目标模式。正式采集前核对实测帧率，现场手册建议至少 28.5 fps。 |
| 从臂 | 实际 SocketCAN 接口为 1 Mbps，现场自检收到电机应答并报告 `FOLLOWER_CAN_READY`。 |
| 主臂 | 从实际 USB 串口或 UART 通讯，现场自检读到 ID 0–7。 |

```bash
lumos-runtime inspect
ip -details link show type can
```

## D–E. 校准与遥操作

用当前主从臂重新生成并激活校准。按合作方工具核对参考姿态、六轴方向与范围、夹爪闭合和张开。清空工作区，准备硬件急停并安排现场监护，随后按手册逐轴小幅试动，确认六轴跟随和夹爪方向。结束时按工具规定停机并确认从臂已安全停止。

### 启动前对齐预览

用 `lumos-runtime plan-startup-alignment` 从机械臂参考角反算遥操作臂目标。输入六个遥操作臂编码器角度（按舵机 ID 0–5 排列）。默认使用机械臂已保存的参考姿态，也可以用 `--mechanical-rad` 输入另一次实测姿态（按机械臂 J1–J6 排列）。

```bash
lumos-runtime plan-startup-alignment /path/to/calibration.json --operator-deg 10 20 30 40 50 60
```

输出包含各轴目标角、角度差和目标是否落在校准范围内。超出范围的目标不能用该组标定对齐。此命令只读输入文件并输出预览，不连接设备。

现场 X5 已验证「遥操作臂对齐、再启动机械臂跟随」的顺序。对齐期间机械臂保持失能，目标采用已保存的参考姿态。到位后复读六轴编码器，确认误差再交接到跟随。若初始偏差超出试验范围、反馈中断或对齐失败，先检查摆位与校准，再启动下一轮。见 [实机记录](teleoperation-2026-11-24.md#启动对齐与重力补偿)。

## F–J. 采集、训练与推理

完成遥操作验收后再采少量完整样本。保留原始数据，生成独立的对齐数据集并通过结构、时序和视频解码校验。之后用 GPU 工作站训练和提供推理服务，最后在 X5 联调，分别记录网络握手和真机验收结果。
